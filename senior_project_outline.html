ส่วนนำ ส่วนประกอบตอนต้น (Preliminary Pages)
มาตรฐานบัณฑิตวิทยาลัย
  • 1. ปกนอก / ปกใน (Cover Pages)
    ชื่อโครงงาน (ไทย/อังกฤษ), ชื่อผู้จัดทำ, อาจารย์ที่ปรึกษา, ภาควิชา, คณะ, สถาบันการศึกษา และปีการศึกษา
  • 2. ใบรับรองโครงงาน (Approval Form)
    ลายเซ็นคณะกรรมการสอบโครงงาน, อาจารย์ที่ปรึกษาหลัก และหัวหน้าภาควิชา
  • 3. บทคัดย่อภาษาไทย และ ภาษาอังกฤษ (Thai & English Abstract)
    สรุปปัญหา, วัตถุประสงค์, นวัตกรรม (Google Maps Parsing, Auto-Scroll Pulse), ผลการทดสอบ และประโยชน์ที่ได้ (ไม่เกิน 1 หน้า)
  • 4. กิตติกรรมประกาศ และ สารบัญ (Acknowledgements & Table of Contents)
    ขอบคุณผู้สนับสนุน, สารบัญเนื้อหา (Table of Contents), สารบัญตาราง (List of Tables), และสารบัญภาพ (List of Figures)
บทที่ 1 บทนำ (Introduction)
ความเป็นมาและกรอบเป้าหมาย
  • 1.1 ความเป็นมาและความสำคัญของปัญหา (Background and Problem Statement)
    - สถานการณ์อุทกภัยในไทยและปัญหาคอขวดด้านการสื่อสารขอความช่วยเหลือ
    - ปัญหาป้ายบ้าน/ป้ายซอยจมน้ำ ทำให้ระบุพิกัดไม่ได้ เกิดการวนเรือค้นหา
    - ข้อมูลกระจัดกระจายบนโซเชียลมีเดีย เกิดเคสซ้ำซ้อน และสายด่วนโทรศัพท์สายไม่ว่าง
  • 1.2 วัตถุประสงค์ของโครงงาน (Objectives)
    1. พัฒนาระบบรับแจ้งเหตุฉุกเฉินที่รองรับทั้ง GPS ดาวเทียม และการแปลงลิงก์ Google Maps เป็นพิกัดอัตโนมัติ
    2. พัฒนาระบบนำทางฟอร์มแบบกะพริบเน้นสายตา (Bounce-Pulse Auto-Scroll) แก้ปัญหาผู้ใช้ตื่นตระหนกกรอกข้อมูลไม่ครบ
    3. พัฒนาระบบแผนที่สถานการณ์เรียลไทม์ (Live Crisis Map) และกระดานคัดกรองงานกู้ภัย (Rescue Dispatch Feed)
  • 1.3 ขอบเขตของโครงงาน (Project Scope)
    - ขอบเขตกลุ่มผู้ใช้: ประชาชนผู้ประสบภัย, เจ้าหน้าที่กู้ภัยที่ยืนยันตัวตน (Verified Rescuer), ผู้ดูแลระบบ (Admin)
    - ขอบเขตการทำงาน: ฟอร์ม SOS, แผนที่ระดับน้ำ, รายการงานกู้ภัย, ปุ่มโทรออกด่วน, ระบบแชร์ LINE
  • 1.4 ประโยชน์ที่คาดว่าจะได้รับ (Expected Benefits)
    ลดเวลาส่งต่อพิกัด, คัดกรองกลุ่มเปราะบาง (ผู้ป่วยติดเตียง/เด็กเล็ก) ได้รวดเร็ว, ป้องกันข้อมูลซ้ำซ้อน
  • 1.5 แผนการดำเนินงานและตารางเวลา (Timeline / Gantt Chart)
    ตารางแผนการดำเนินงาน 14 สัปดาห์ (ศึกษาข้อมูล → ออกแบบ → พัฒนา → ทดสอบ → ใช้งานจริง)
บทที่ 2 ทฤษฎี วรรณกรรม และเทคโนโลยีที่เกี่ยวข้อง (Literature & Technologies)
กรอบแนวคิดวิชาการ
  • 2.1 สารสนเทศในภาวะวิกฤต (Crisis Informatics & Disaster Management)
    ทฤษฎีการจัดการสารสนเทศฉุกเฉิน และหลักการคัดกรองระดับความเร่งด่วนตามหลักการแพทย์ฉุกเฉิน (Triage)
  • 2.2 ระบบสารสนเทศภูมิศาสตร์ (GIS) และสูตรฮาเวอร์ซีน (Haversine Formula)
    การคำนวณระยะทางทรงกลมระหว่างพิกัดกู้ภัยกับผู้ประสบภัยบนพื้นผิวโลก เพื่อจัดเรียงลำดับเคสใกล้-ไกล
  • 2.3 การถอดรหัสพิกัดจาก URL ด้วย Regular Expressions (Regex Parsing)
    การวิเคราะห์โครงสร้าง URL ของ Google Maps (?q=, @lat,lng, embedded coordinates) เพื่อแปลงเป็น ละติจูด/ลองจิจูด
  • 2.4 เทคโนโลยีส่วนต่อประสาน (Modern Frontend Architecture)
    React 19 TypeScript Vite Tailwind CSS v4 Leaflet & OpenStreetMap
  • 2.5 สถาปัตยกรรมการยืนยันตัวตนและการควบคุมสิทธิ์ (LINE OAuth & RBAC)
    การล็อกอินด้วย LINE Social Login และการแบ่งบทบาทสิทธิ์ (Citizen vs Verified Rescuer vs Admin)
  • 2.6 ความมั่นคงปลอดภัยเว็บและการป้องกันสแปม (OWASP Top 10 Mitigation)
    การป้องกัน Stored XSS, Anti-Spam Rate Limiting (Cooldown 60s), Clickjacking และการป้องกัน IDOR
บทที่ 3 การวิเคราะห์และออกแบบระบบ (System Analysis and Design)
พิมพ์เขียวระบบ
  • 3.1 สถาปัตยกรรมระบบโดยรวม (System Architecture Diagram)
    การเชื่อมต่อระหว่าง Client Presentation Layer, Application Logic Layer และ Data/External API Services
  • 3.2 แผนภาพกรณีการใช้งานและผู้ใช้ (Use Case Diagram & Actor Matrix)
    แผนภาพ Use Case จำแนกหน้าที่ระหว่าง Citizen (แจ้งเหตุ), Rescuer (รับเคส/นำทาง/โทร), Admin (รับรอง/จัดการระบบ)
  • 3.3 แผนภาพกระบวนการทำงาน (Activity / Workflow Diagram)
    Workflow การส่งข้อมูล SOS, กระบวนการตรวจสอบและเลื่อนจออัตโนมัติ (Bounce-Pulse), และวงจรสถานะเคส (Pending → Completed)
  • 3.4 โครงสร้างข้อมูลและแบบจำลองข้อมูล (Data Model & Schema Definitions)
    นิยามโครงสร้าง SOSRequest, Coordinates, PeopleCount, UserProfile, UrgencyLevel, WaterLevel ใน TypeScript
  • 3.5 การออกแบบส่วนต่อประสานผู้ใช้ (UI/UX Emergency Design System)
    การออกแบบ Touch Target ขนาดใหญ่สำหรับมือถือ, สีสัญลักษณ์กู้ภัยสากล (แดง-ส้ม-เขียว-น้ำเงิน), และการตัดปุ่มที่ซ้ำซ้อน
บทที่ 4 ผลการดำเนินงานและการทดสอบระบบ (Implementation and Testing)
ผลงานและการทดสอบ
  • 4.1 ผลการพัฒนาฟังก์ชันการทำงานหลัก (System Implementation Results)
    หน้าฟอร์ม SOS พร้อม GPS และแปลงลิงก์ Google Maps, แผนที่ Live Crisis Map, และกระดานคัดกรอง Rescue Feed
  • 4.2 ผลการทำงานของอัลกอริทึม Auto-Scroll & Visual Bounce-Pulse
    การตัดหน้าต่างป๊อปอัปออกทั้งหมด แล้วเลื่อนหน้าจอตรงไปยังช่องบนสุดที่ยังไม่ได้กรอกทันที พร้อมเอฟเฟกต์กะพริบขยายขนาด
  • 4.3 ผลการทดสอบการทำงานตาม Use Cases (Functional Test Matrix)
    ตารางทดสอบ 8 กรณีทดสอบหลัก (TC-01 ถึง TC-08): ดึงพิกัด GPS, ถอดรหัส URL แผนที่, ตรวจจับข้อมูลว่าง, ป้องกันสแปม, และควบคุมสิทธิ์กู้ภัย (ผ่าน 100%)
  • 4.4 รายงานการทดสอบและแก้ไขช่องโหว่ความปลอดภัย (Security Audit)
    ผลการทดสอบการป้องกัน Stored XSS, Rate Limiting, Role Verification Bypass, และ Clickjacking
บทที่ 5 สรุปผลการดำเนินงาน อภิปรายผล และข้อเสนอแนะ (Conclusions & Future Work)
บทสรุปและการต่อยอด
  • 5.1 สรุปผลการดำเนินงาน (Conclusions)
    สรุปความสำเร็จของโครงงานตามวัตถุประสงค์ การลดระยะเวลากรอกข้อมูล และความแม่นยำในการนำทางกู้ภัย
  • 5.2 อภิปรายผลและจุดเด่นของระบบ (Discussion & Key Highlights)
    Zero-Cost High Availability Architecture, Human-Centered Emergency Design, และการจำแนกกลุ่มเปราะบาง
  • 5.3 ปัญหา อุปสรรค และแนวทางแก้ไข (Limitations & Mitigation)
    ปัญหาเสาสัญญาณเน็ตล่มในพื้นที่น้ำท่วมสูง (แก้ไขด้วย Offline SMS Template) และปัญหาลิงก์ย่อ Google Maps
  • 5.4 ข้อเสนอแนะและการพัฒนาต่อยอดในอนาคต (Future Enhancements)
    1. บูรณาการ AI WeatherNext 3 (Google DeepMind) พยากรณ์น้ำท่วมล่วงหน้า 3–7 วัน
    2. เชื่อมโยงระบบเข้ากับ API ศูนย์สั่งการสายด่วน 1669 และกรมป้องกันและบรรเทาสาธารณภัย (ปภ.)
    3. พัฒนาระบบส่งสัญญาณ SOS ผ่านคลื่นวิทยุไร้สายระยะไกล (LoRa Mesh Network)
